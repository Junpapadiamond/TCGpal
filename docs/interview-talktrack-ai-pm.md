# 面试 talk track — 国内大厂 AI PM（TCGpal）

定位：这是个人项目,不是上线产品。面试目标不是证明 PMF,是展示**AI 产品判断力、落地能力、结构化思维**。国内大厂 AI PM 最看重:知道哪里该用大模型、AI 产品的可信度/控幻觉设计、agent/智能体设计、效果评估(eval)、成本意识、数据飞轮与商业化。

---

## 一句话 hook（30 秒电梯版）
"TCGpal 是给卡牌玩家的'买前检查'智能体。这个品类全是放大 FOMO 的工具,我想反过来做一件事:在用户冲动下单前,用一个 AI agent 帮他把'自己没时间查、容易被情绪忽略'的证据(版本、预算、成交价、品相)查齐、对齐、讲清楚,再给一个冷静建议。**它的核心不是让 AI 替用户决定,而是把 AI 放在它真正不可替代的地方。**"

## 2 分钟版（问题 → 洞察 → 关键决策 → 复盘）
- **问题**:卡牌玩家买卡常被"现在不买就涨了"推着走,市面工具又都在喂这种情绪。
- **洞察**:真正该用 AI 的不是"加个聊天框"或"预测涨跌",而是补齐用户决策时缺失的证据。这是个**证据问题,不是预测问题**。
- **关键决策**:核心逻辑(预算、EV 数学、风险规则)做成纯确定性代码,AI 只做它擅长的——从混乱文本抽取、对齐版本、发现证据缺口、整理成人话。AI 之上再用确定性护栏兜底。
- **结果/复盘**:Claude agent 路径跑通,实际编排 5 个工具,预算硬停在代码层强制覆盖模型。最大复盘:还没用真实用户验证核心行为假设,且重模型对一个"停 30 秒"的场景成本偏高——这两点我都有明确的下一步。

---

## Deep-dive 弹药库（5 个 STAR 故事,按 AI PM 重心排序）

### 1. AI 放在哪——核心判断力
- **S**:买卡决策里既有需要判断的混乱信息(版本/品相/成交价),也有纯确定性的部分(预算、EV)。
- **T**:决定 AI 在产品里扮演什么角色,避免"为了用 AI 而用 AI"。
- **A**:把 raw-vs-slab、listing-risk、预算规则全做成纯确定性 TypeScript;AI 只负责抽取、对齐、判断证据缺口、生成自然语言建议。
- **R**:模型职责小、可控、可测、便宜,没有 key 也能跑(回退确定性)。
- **信号**:知道**什么时候不该用大模型**——AI PM 最稀缺的判断,多数人只会无脑加 AI。

### 2. 可信度 / 控幻觉设计
- **S**:AI 产品最大障碍是信任,尤其涉及钱。
- **T**:让用户敢信这个 verdict,且系统不能乱编。
- **A**:三层防线——① 确定性预算硬停**强制覆盖**模型(模型不能突破预算红线);② 成交价没接数据源时**诚实标 unavailable**,绝不编造;③ 模型/key 失败**自动回退**本地确定性,且不向用户暴露报错堆栈。
- **R**:系统宁可说"我不知道",也不假装查过。
- **信号**:把"控幻觉"当**产品设计问题**而非纯技术问题——AI 落地的核心能力。

### 3. 为什么是 Agent,不是一次 prompt
- **S**:买前检查要去多个地方查、从混乱信息抽取、判断版本是否一致、对比成交价——单次调用做不到。
- **T**:设计成多步智能体。
- **A**:Market Check Agent 编排 5 个工具:识别精确版本 → 取参考价 → 取成交 comps → 检查证据缺口 → 跑确定性预算规则,最后由确定性规则做最终护栏。
- **R**:实际调用全部 5 个工具,fallback 未触发。
- **信号**:能讲清 **agent vs workflow vs 单次调用** 的边界——什么任务才"配得上"agent。

### 4. 效果怎么评估（eval）
- **S**:AI 产品不能凭感觉说"好像还行"。
- **T**:在换数据源/模型时知道 agent 有没有静默变坏。
- **A**:做了 eval harness——路由正确性、schema 校验、确定性数学正确性、安全话术(不承诺利润/不保证评级)、模型成本守卫。
- **R**:改动时有回归防线。
- **信号**:AI PM 懂 eval 是稀缺信号,体现"对 AI 效果负责"。

### 5. 成本取舍 + 自我复盘
- **S**:opus 跑 5 工具约 16 秒,对"停 30 秒"的轻量场景又慢又贵。
- **T**:判断模型选型是否匹配场景。
- **A**:识别为错配,规划:编排用轻模型(haiku/sonnet),重模型只做最终推理;卡片身份、参考价做缓存,减少调用。
- **R**:(规划中)——同时这是"重来会怎么改"的好料。
- **信号**:成本意识 + 复盘能力,大厂极看重。

## AI PM 专属追问——提前备好

- **"你怎么理解 agent?"** → 需要多源查询 + 信息抽取 + 一致性判断 + 证据缺口检测的任务才需要 agent;否则单次调用就够。
- **"幻觉怎么控?"** → 故事 2:确定性硬护栏 + 诚实 unavailable + 失败回退;**关键钱相关的计算绝不交给会幻觉的模型**。
- **"AI 效果怎么评估?"** → eval harness + 北极星(见下)。
- **"北极星指标是什么?"** → 不是 DAU,是**决策质量**类:verdict 采纳率、用户事后认可率(后悔购买率↓)、fallback 率(AI 可用性)、工具调用成功率、单次决策成本。
- **"成本怎么控?"** → 模型分层 + 缓存 + 确定性兜底减少不必要调用。
- **"如果在我们公司做大,怎么规模化/商业化?"** → **数据飞轮**:决策日志 → 行为记忆 → 个性化 verdict,越用越准、越准越留;数据源走官方合作(eBay/评级机构/国内平台);商业模式可选会员订阅 / 增值数据 / 交易抽佣。
- **"为什么不直接让大模型全做?"** → 涉及钱必须可控、可测、可复现;确定性兜底 + AI 薄层是落地必然选择。

## 把弱点变资产
主动说:"这个项目最大的缺口是我从自己对问题的理解出发,**还没用真实用户验证'冲动时人会不会停下来'这个核心假设**。如果继续做,我会先做 5-10 个用户访谈专门测这一点。" —— 主动暴露弱点 + 给出验证方法,本身就是资深信号,比假装已验证强得多。

## 国内大厂表达建议
- **结构化**:先结论后展开,STAR,别功能巡览。
- **量化一切**:即使没有用户数据,也讲过程指标(工具数、延迟、fallback 率、覆盖维度)。
- **黑话用对**:大模型、智能体、提效、北极星、数据飞轮/闭环、抓手、落地、护栏、回退、复盘。
- **强调落地**:你把 agent **真跑通了**,不是 PPT——这是大厂分辨"真 AI PM vs 概念 PM"的关键。
- **准备数据飞轮叙事**:大厂最爱"越用越值钱"的闭环。
- **体现商业 sense**:能从产品自然过渡到规模化和商业化。

## 不要踩的坑
- 别吹"用户很喜欢"——没用户,被问"多少 DAU"会塌。诚实说"个人项目、未上线,目标是练 X"。
- 别陷进纯技术细节——你是面 PM,落点要回到"为用户/为业务解决了什么、判断逻辑是什么"。
