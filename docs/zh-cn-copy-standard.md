# TCGlens 简体中文文案规范（给 coding agent 的执行标准）

> 目标读者：执行文案改写任务的 coding agent。
> 目标：让中文版读起来像一个懂卡的中国玩家写的，而不是从英文翻过来的。
> 适用范围：`src/features/comparison/i18n.tsx`、`src/features/comparison/verdict-copy.ts`、`src/features/comparison/receipt-summary.ts`、`src/features/receipt/ReceiptPageClient.tsx`、`src/app/method/MethodPageClient.tsx`、`src/lib/ai/comparison-qa.ts`，以及今后所有新增中文文案。

---

## 1. 语气人设

写文案时脑子里的人设：**一个常年在 eBay/卡淘/闲鱼买裸卡的老玩家，在帮朋友看单。**

- 用"你"，不用"您"。
- 直接说事，不绕弯。"没搜到就是没搜到"，不要"很遗憾地通知您未能检索到"。
- 可以有一点口语，但不油、不卖萌、不用网络烂梗。
- 谨慎的话要明说（"品相是卖家自己说的，下单前去商品页再看一眼"），这和产品 guardrail 一致：不替用户做决定、不预测评级、不打包票。
- 专业判断要短。"先排除错版和离谱低价，再找最低总价"比"在排除了不可比商品之后，我们为您计算了最低可比总价"好。

## 2. 语言红线（AI 腔 / 翻译腔黑名单）

### 2.1 禁止出现的词和句式

| 类型 | 黑名单 | 怎么改 |
|---|---|---|
| AI 高频词 | 此外、值得注意的是、至关重要、深入、赋能、彰显、无缝、格局、持久、宝贵 | 删掉或换成具体说法 |
| 翻译腔连接词 | 基于、对于……来说、在……的情况下、就……而言、由于……的事实 | 重写句子 |
| 动词名词化 | "进行比对""进行核验""做出推荐" | 直接用动词："比""核对""推荐" |
| 系动词回避 | "作为""充当""是……的体现" | 用"是""有" |
| 被动堆砌 | "商品被筛选掉" | "筛掉了这件商品" / "已筛掉" |
| 三段式 | "快速、准确且可靠" | 最多两项，或直接说具体事实 |
| 谄媚/客服腔 | 希望这对你有帮助、感谢您的理解与支持、敬请期待 | 全部删除 |
| 台湾/技术腔 | 回传、资讯、预设、串接、脸部（Facebook 叫"脸书"也算） | 回传→返回/报；脸书→Facebook |

### 2.2 节奏

- 相邻三句话长度不要一样。长的解释句后面跟一句短的。
- 按钮和标签能两个字解决就不要四个字："比较确切商品"→"开始比价"。
- 一句只说一件事。英文原句是复合句时，中文拆成两句往往更顺。

## 3. 术语表（唯一标准，全项目统一）

> "标准译法"列是唯一允许出现的写法。现有文案里的其他写法一律改掉。
> 括号内英文缩写保留，因为 eBay 卖家和卡圈交流本来就用这些缩写。

### 3.4 卖家/风险标签（card 区标签统一为这组）

| 英文 | 标准译法 |
|---|---|
| Trusted seller | 可信卖家 |
| Decent seller | 信誉尚可 |
| Unproven seller | 记录太少 |
| Unverified seller | 卖家信息不足 |
| Photo-rich | 照片充足 |
| Some photos | 有部分照片 |
| Thin evidence | 证据很少 |
| Low risk | 低风险 |
| Some risk | 有一定风险 |
| Higher risk | 风险偏高 |
| Unverified | 信息不足 |
| Top pick / Our pick | 首选 |

规则：标签说的是"这件商品/这个卖家"，不要用"用户"。**用户自己添加的东西写"你添加的"，不写"用户添加"。**

## 4. 格式规范

1. **标点**：中文句子用全角标点（，。：；？！）。括号：句子里夹中文说明用全角（），纯英文缩写/代码用半角 ()，如"近全新（NM）"、"215/203"。
2. **空格**：中文与英文单词/数字之间加一个半角空格（"已比对 12 件商品"、"好评率 99.5%"）。数字与中文量词之间同样空格（"3 张照片"）。
3. **货币**：产品是美国市场，**金额一律 `$`（美元），禁止换算或改写成 ¥**。`$` 紧贴数字：`$45.00`。
4. **百分号**：紧贴数字，`99.5%`。
5. **量词**：商品/链接/评价 → 条；照片 → 张；版本/候选/来源 → 个。
6. **日期**：`2026/8/9` 或"8 月 9 日"，不要 `2026-08-09` 这种数据库格式直接怼用户脸上（技术核验记录区除外）。
7. **省略号**：用 `…`，现有代码已统一，保持。
8. **引号**：强调/引用用「」，不用弯引号 ""。
9. **破折号**：一句最多一个，能拆句就拆句。

## 5. 已知必改清单（现状审计结果）

以下是逐文件核对后发现的**实际错误或不一致**，不是风格建议，必须改：

1. **品相标签三个文件三套译法**（最严重）：
   - `i18n.tsx` / `verdict-copy.ts`：轻度磨损/中度磨损/重度磨损/破损
   - `ReceiptPageClient.tsx`：轻度使用/中度使用/重度使用/损坏
   - 全部统一为术语表 3.1 的写法：微瑕（LP）/ 明显瑕疵（MP）/ 重度瑕疵（HP）/ 损卡。
2. **`result.avoidedTraps` 是误译**（`i18n.tsx`）：英文 "look-alikes, far-below-market, or wrong version" 指"看着像但不是那张卡的版本、价格远低于市价、版本对不上"，现在翻成了"仿品"——这违反 guardrail（不能暗示卖家卖假货）。改为"已帮你筛掉 N 件有问题的商品：同名不同卡、价格低得离谱，或版本对不上"。
3. **"凭据/凭证"混用**：`decisionReceipt/shareReceipt` 用了"凭据"，`ReceiptPageClient.tsx` 用了"凭证"。统一为"决策凭证/分享凭证/复制凭证"。同时 `demoBody` 里的"eBay 凭据"指 API credentials，改为"eBay 接口密钥"。
4. **"视角/角度"混用**：`lens` 相关文案里"你的默认视角""本角度第一""最稳妥角度得分"并存，统一为"视角"。
5. **demoTitle 是病句**："标注的示例库存。" → "这是示例数据。"
6. **error.temporary 台湾腔**："比对服务这次回传了临时错误，而不是正式报告" → "服务临时出了点错，没出结果。现在重试就行；一直失败的话，去「方法」页看看来源状态。"
7. **"用户添加/用户提供的候选"** → "你添加的 / 你提供的"。
8. **ledgerHelp 里的"脸书"** → Facebook；"本地店" → 本地卡店；Mercari 首次出现补"（煤炉）"。
9. **"Local shop" 译法**：marketplaces 里 "本地店" → "本地卡店"。
10. **hero.title 翻译腔**："为确切版本找到最值得买的商品。" → "认准你要的那张卡，挑出最值得买的一件。"
11. **submitIdle 翻译腔**："比较确切商品" → "开始比价"。
12. **noLiveCandidates "没有实时结果"** → "没有在卖的商品"。
13. **cautionFewLenses 病句**："可比证据不足，少于三个角度能给出结果。" → "证据不够，四个视角里能给出结论的不到三个。"
14. **信息不足的卖家**（label）→ "卖家信息不足"。
15. **One Piece 占位符/提示**：出现 One Piece 中文名的地方统一"海贼王"。

## 7. 给 coding agent 的执行流程

1. **只改字符串值，不改 key、不改函数签名、不改 `Dict` 类型结构。** 英文词典是 source of truth，逐 key 核对 zh 词典。
2. 先按第 5 节必改清单逐项修复，再按术语表全量过一遍 `i18n.tsx` 的 zh 对象、`verdict-copy.ts`、`receipt-summary.ts`、`ReceiptPageClient.tsx`、`MethodPageClient.tsx`、`comparison-qa.ts` 里的中文。
3. 更新测试断言里的中文字符串（`i18n.test.ts`、`verdict-copy.test.ts`、`ReceiptPageClient.test.tsx`、`ComparisonApp.test.tsx`、`receipt-summary.test.ts`），然后跑：
   ```bash
   npx vitest run src/features/comparison src/features/receipt
   ```
4. 一致性自查（改完后这些 grep 应该只命中术语表允许的写法）：
   ```bash
   rg -n "轻度磨损|轻度使用|中度磨损|中度使用|重度磨损|重度使用|未评级单卡|收藏编号|凭据|脸书|本地店|本角度|角度得分|示例库存|回传|用户添加|用户提供" src/
   rg -n "破损|损坏" src/   # 品相语境只允许"损卡"
   ```
5. 人工走查清单（UI 里逐屏看）：
   - 切换中文后，首页 / 版本确认页 / 结果页 / 证据清单 / 决策凭证页 / 方法页各看一遍；
   - 每个标签念出来，不像人话就打回；
   - 检查全角/半角标点、数字前后空格、量词。

## 8. 新增文案时怎么写

1. 先查术语表，有术语必须用术语表。
2. 写完自己念一遍。拗口就拆短。
3. 过一遍第 2 节黑名单。
4. 不确定玩家怎么叫的，宁可直白描述，不要造词。
